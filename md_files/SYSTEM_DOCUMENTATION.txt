2. DATABASE SCHEMA
================================================================================

2.1 USERS TABLE (users)
   Fields:
   • id                         - BIGINT UNSIGNED, PRIMARY KEY, AUTO_INCREMENT
   • name                       - VARCHAR(255), NOT NULL
   • email                      - VARCHAR(255), UNIQUE, NOT NULL
   • email_verified_at          - TIMESTAMP, NULLABLE
   • password                   - VARCHAR(255), NOT NULL
   • google_id                  - VARCHAR(255), NULLABLE, INDEX
   • avatar                     - VARCHAR(255), NULLABLE
   • two_factor_secret          - TEXT, NULLABLE
   • two_factor_recovery_codes  - TEXT, NULLABLE
   • two_factor_confirmed_at    - TIMESTAMP, NULLABLE
   • two_factor_method          - ENUM('email', 'totp'), NULLABLE
   • email_two_factor_code      - VARCHAR(6), NULLABLE
   • email_two_factor_expires_at - TIMESTAMP, NULLABLE
   • is_admin                   - BOOLEAN, DEFAULT: false
   • is_active                  - BOOLEAN, DEFAULT: true
   • role_id                    - BIGINT UNSIGNED, NULLABLE, FOREIGN KEY
   • created_by                 - BIGINT UNSIGNED, NULLABLE, FOREIGN KEY
   • remember_token             - VARCHAR(100), NULLABLE
   • created_at                 - TIMESTAMP
   • updated_at                 - TIMESTAMP

   Relationships:
   • Belongs to one Role (role_id → roles.id)
   • Belongs to one Creator User (created_by → users.id)
   • Has many Created Users

2.2 ROLES TABLE (roles)
   Fields:
   • id             - BIGINT UNSIGNED, PRIMARY KEY, AUTO_INCREMENT
   • name           - VARCHAR(255), NOT NULL
   • slug           - VARCHAR(255), UNIQUE, NOT NULL
   • description    - VARCHAR(500), NULLABLE
   • is_system      - BOOLEAN, DEFAULT: false
   • created_at     - TIMESTAMP
   • updated_at     - TIMESTAMP

   Relationships:
   • Has many Users
   • Has many Permissions (through role_permission pivot)

2.3 PERMISSIONS TABLE (permissions)
   Fields:
   • id             - BIGINT UNSIGNED, PRIMARY KEY, AUTO_INCREMENT
   • name           - VARCHAR(255), NOT NULL
   • slug           - VARCHAR(255), UNIQUE, NOT NULL
   • description    - VARCHAR(500), NULLABLE
   • module         - VARCHAR(100), NULLABLE
   • is_system      - BOOLEAN, DEFAULT: false
   • created_at     - TIMESTAMP
   • updated_at     - TIMESTAMP

   Relationships:
   • Belongs to many Roles (through role_permission pivot)

2.4 ROLE_PERMISSION TABLE (role_permission) - Pivot Table
   Fields:
   • id             - BIGINT UNSIGNED, PRIMARY KEY, AUTO_INCREMENT
   • role_id        - BIGINT UNSIGNED, NOT NULL, FOREIGN KEY
   • permission_id  - BIGINT UNSIGNED, NOT NULL, FOREIGN KEY
   • created_at     - TIMESTAMP
   • updated_at     - TIMESTAMP

   Indexes:
   • Composite Unique Index on (role_id, permission_id)
   • Index on role_id
   • Index on permission_id

2.5 PASSWORD_SETUP_TOKENS TABLE (password_setup_tokens)
   Fields:
   • id             - BIGINT UNSIGNED, PRIMARY KEY, AUTO_INCREMENT
   • user_id        - BIGINT UNSIGNED, NOT NULL, FOREIGN KEY
   • token          - VARCHAR(64), UNIQUE, NOT NULL, INDEX
   • expires_at     - TIMESTAMP, NOT NULL
   • created_at     - TIMESTAMP
   • updated_at     - TIMESTAMP

   Relationships:
   • Belongs to one User

2.6 PASSWORD_RESET_TOKENS TABLE (password_reset_tokens)
   Fields:
   • email          - VARCHAR(255), PRIMARY KEY
   • token          - VARCHAR(255), NOT NULL
   • created_at     - TIMESTAMP, NULLABLE

2.7 SESSIONS TABLE (sessions)
   Fields:
   • id             - VARCHAR(255), PRIMARY KEY
   • user_id        - BIGINT UNSIGNED, NULLABLE, INDEX
   • ip_address     - VARCHAR(45), NULLABLE
   • user_agent     - TEXT, NULLABLE
   • payload        - LONGTEXT, NOT NULL
   • last_activity  - INTEGER, NOT NULL, INDEX

2.8 CACHE TABLE (cache)
   Fields:
   • key            - VARCHAR(255), PRIMARY KEY
   • value          - MEDIUMTEXT, NOT NULL
   • expiration     - INTEGER, NOT NULL

2.9 CACHE_LOCKS TABLE (cache_locks)
   Fields:
   • key            - VARCHAR(255), PRIMARY KEY
   • owner          - VARCHAR(255), NOT NULL
   • expiration     - INTEGER, NOT NULL

2.10 JOBS TABLE (jobs)
   Fields:
   • id             - BIGINT UNSIGNED, PRIMARY KEY, AUTO_INCREMENT
   • queue          - VARCHAR(255), NOT NULL, INDEX
   • payload        - LONGTEXT, NOT NULL
   • attempts       - TINYINT UNSIGNED, NOT NULL
   • reserved_at    - INTEGER UNSIGNED, NULLABLE
   • available_at   - INTEGER UNSIGNED, NOT NULL
   • created_at     - INTEGER UNSIGNED, NOT NULL

2.11 JOB_BATCHES TABLE (job_batches)
   Fields:
   • id             - VARCHAR(255), PRIMARY KEY
   • name           - VARCHAR(255), NOT NULL
   • total_jobs     - INTEGER, NOT NULL
   • pending_jobs   - INTEGER, NOT NULL
   • failed_jobs    - INTEGER, NOT NULL
   • failed_job_ids - LONGTEXT, NOT NULL
   • options        - MEDIUMTEXT, NULLABLE
   • cancelled_at   - INTEGER, NULLABLE
   • created_at     - INTEGER, NOT NULL
   • finished_at    - INTEGER, NULLABLE

2.12 FAILED_JOBS TABLE (failed_jobs)
   Fields:
   • id             - BIGINT UNSIGNED, PRIMARY KEY, AUTO_INCREMENT
   • uuid           - VARCHAR(255), UNIQUE, NOT NULL
   • connection     - TEXT, NOT NULL
   • queue          - TEXT, NOT NULL
   • payload        - LONGTEXT, NOT NULL
   • exception      - LONGTEXT, NOT NULL
   • failed_at      - TIMESTAMP, NOT NULL, DEFAULT: CURRENT_TIMESTAMP

3. AUTHENTICATION MODULE
================================================================================

3.1 AUTHENTICATION FEATURES
   • Email/Password Login
   • Google OAuth Login
   • Two-Factor Authentication (2FA)
     - Email-based OTP
     - TOTP (Time-based One-Time Password)
   • Password Reset Flow
   • Welcome Email with Password Setup
   • Remember Me Functionality
   • Session Management

3.2 AUTHENTICATION FLOW
   • User Registration → Admin Creates User
   • Welcome Email Sent → Contains Password Setup Link
   • User Sets Password → Redirected to Login
   • 2FA Automatically Enabled → Email 2FA by Default
   • Login → Email/Password → 2FA Challenge → Dashboard

3.3 AUTHENTICATION CONTROLLERS
   • AuthenticatedSessionController
     - Login/Logout handling
     - Session management
   • GoogleController
     - OAuth callback handling
     - Account linking
   • PasswordSetupController
     - Welcome email password setup
     - Token validation
   • TwoFactorAuthenticatedSessionController
     - 2FA verification
     - Code validation
   • TwoFactorSetupController
     - 2FA method selection
     - TOTP setup and verification

3.4 AUTHENTICATION MIDDLEWARE
   • auth - Requires authenticated user
   • guest - Only for non-authenticated users
   • verified - Requires email verification
   • two-factor - Enforces 2FA setup
